# IP 地址存储选型：数据库里 IP 该用什么类型存

## 一句话
别用 `varchar` 把 IP 当文字存：**IPv4 转成整数存 `INT UNSIGNED`（4 字节），IPv6 转成 16 字节二进制存 `VARBINARY(16)`**。

## 为什么会有这个问题
`192.168.1.1` 只是**给人看的写法**，就像门牌号「幸福路 88 号 3 单元 501」。

数据库如果原样把这串文字抄进去，等于每次都要抄一整行地址，有三个毛病：
1. **占地方**：`varchar(15)` 最多 15 字节，整数只要 4 字节；
2. **比大小会乱**：字符串是按字典序比的，`192.168.1.10` 会排在 `192.168.1.9` 前面；
3. **查网段麻烦**：只能拼 `LIKE '192.168.1.%'`，慢还容易误伤。

其实 IP 背后就是 **4 个 0~255 的数字**拼起来的，把它当成一个「编号」存下来，问题全没了。

## 怎么做

### IPv4：存成整数（`INT UNSIGNED`，4 字节）
MySQL 自带两个函数，帮你做「字符串 ↔ 整数」的翻译：

| 函数 | 作用 | 例子 |
|---|---|---|
| `INET_ATON('192.168.1.1')` | 字符串 → 整数（ATON = ASCII to Number） | 得到 `3232235777` |
| `INET_NTOA(3232235777)` | 整数 → 字符串 | 得到 `'192.168.1.1'` |

这个整数怎么来的？把 4 段数字当成 **256 进制**拼起来：

```
192 × 256³ + 168 × 256² + 1 × 256 + 1 = 3232235777
```

建表和查询长这样：

```sql
CREATE TABLE user_log (
  id      BIGINT UNSIGNED PRIMARY KEY,
  ip_num  INT UNSIGNED NOT NULL,   -- 4 字节，能存 0 ~ 4294967295
  KEY idx_ip (ip_num)
);

-- 存：先转成整数再写库
INSERT INTO user_log (id, ip_num) VALUES (1, INET_ATON('192.168.1.1'));

-- 查：拿整数去匹配，返回时再转回字符串给人看
SELECT INET_NTOA(ip_num) FROM user_log WHERE ip_num = INET_ATON('192.168.1.1');
```

### IPv6：存成 16 字节二进制（`VARBINARY(16)`）
IPv6 是 **128 位**，正好 16 字节，整数装不下，所以用二进制：

```sql
CREATE TABLE login_log (
  id      BIGINT UNSIGNED PRIMARY KEY,
  ip_bin  VARBINARY(16) NOT NULL,  -- 128 位 = 16 字节，不多不少
  KEY idx_ip (ip_bin)
);

-- 对应函数是 INET6_ATON / INET6_NTOA
INSERT INTO login_log (id, ip_bin) VALUES (1, INET6_ATON('2001:db8::1'));
SELECT INET6_NTOA(ip_bin) FROM login_log WHERE ip_bin = INET6_ATON('2001:db8::1');
```

### 三种存法对比

| 存法 | 字段类型 | 占用 | 什么时候用 |
|---|---|---|---|
| 当字符串存 | `varchar(15)` / `varchar(39)` | 15 / 39 字节起 | 只是把 IP 记一笔、几乎不查 |
| IPv4 整数 | `INT UNSIGNED` | **4 字节** | 主流做法：要排序、筛选、统计 |
| IPv6 二进制 | `VARBINARY(16)` | **16 字节** | 必须支持 v6，或想 v4/v6 统一处理 |

> 补充：如果用 ClickHouse 这类分析型数据库做 IP 分析，它**原生就支持 IPv4 / IPv6 类型**，直接建字段就行，不用自己转。标准 MySQL 才需要靠上面的函数。

## 一句提醒（Java 侧的坑）
MySQL 的 `INT UNSIGNED` 最大值是 **4294967295**，而 Java 的 `int` 上限只有 **2147483647**——刚好差一倍。

所以碰到 `128.0.0.0` 以上的 IP（比如 `200.1.1.1` 换算出来约 33.5 亿），**用 `int` 接会溢出成负数**，数据就错了。Java 里必须用 **`long`**（JDBC 用 `rs.getLong(...)`），或者 `BigInteger`。

一句话总结：**IP 存字符串不是不能用，而是「能省则省」——v4 存整数、v6 存二进制，Java 侧记得用 `long` 接。**
