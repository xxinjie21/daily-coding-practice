# 多数据库适配：同一套代码，怎么同时伺候 MySQL 和 Oracle

## 一句话
同一个功能（比如「查商品列表的第 4~8 条」），项目要求既能跑在 MySQL 上、也能跑在 Oracle 上。数据库不同，SQL 写法就不同，但你的业务代码最好一个字都别改。

## 为什么会有这个问题
出门带吹风机最怕插座对不上：中国是两脚扁插，英国是三方块插。吹风机没坏，是**接口形状**对不上。

数据库之间也是这个道理，同一个需求，各家语法不一样：

| 需求 | MySQL | Oracle |
|---|---|---|
| 分页取第 4~8 条 | `LIMIT 5 OFFSET 3` | 老版本没有 LIMIT，只能 `ROWNUM` 套两层子查询 |
| 空值兜底 | `IFNULL(name, '无名')` | `NVL(name, '无名')` |
| 自增主键 | `AUTO_INCREMENT` | 靠 `SEQUENCE` 序列 |

如果代码里到处写 `if (dbType.equals("mysql")) {...} else {...}`，那以后每加一种数据库，就得把整个项目翻一遍——维护直接崩。

## 怎么做：把「会变的」关进小盒子
思路就一句：**业务代码只认接口，方言细节藏在实现里**。分三层（对应原题第 2 点）：

1. **接口层** —— `SqlBuilder`：只说「我要一条分页 SQL、我要一个空值兜底函数」，不说「怎么写」。
2. **实现层** —— `MySqlSqlBuilder` / `OracleSqlBuilder`：各自按自家语法拼 SQL。
3. **路由层** —— `SqlBuilderFactory` 读配置项 `db.type`，决定 new 哪个实现；业务层永远只拿到接口。

调用链长这样：

```
业务代码 ProductDao.findPage()      ← 只调接口，看不到任何方言词
          │
          ▼
    SqlBuilder（接口）
    ├── MySqlSqlBuilder   → LIMIT ? OFFSET ?
    └── OracleSqlBuilder  → ROWNUM 两层嵌套
```

### 关键代码（与 `code/src/main/java/Demo.java` 完全一致）

接口只声明两件事，实现类各写各的方言：

```java
interface SqlBuilder {
    String name();
    PageQuery buildPageQuery(String table, String orderBy, int offset, int limit);
    String buildIfNull(String column, String fallback);
}

class MySqlSqlBuilder implements SqlBuilder {
    @Override
    public PageQuery buildPageQuery(String table, String orderBy, int offset, int limit) {
        String sql = "SELECT id, name FROM " + table + " ORDER BY " + orderBy + " LIMIT ? OFFSET ?";
        return new PageQuery(sql, List.of(limit, offset));
    }
    @Override public String buildIfNull(String column, String fallback) {
        return "IFNULL(" + column + ", '" + fallback + "')";
    }
}

class OracleSqlBuilder implements SqlBuilder {
    @Override
    public PageQuery buildPageQuery(String table, String orderBy, int offset, int limit) {
        String sql = "SELECT * FROM (SELECT t.*, ROWNUM rn FROM "
                + "(SELECT id, name FROM " + table + " ORDER BY " + orderBy + ") t"
                + " WHERE ROWNUM <= ?) WHERE rn > ?";
        // 先取到 offset+limit 行，再把这之前的 offset 行丢掉 —— ROWNUM 只能「小于等于」，不能直接跳过
        return new PageQuery(sql, List.of(offset + limit, offset));
    }
    @Override public String buildIfNull(String column, String fallback) {
        return "NVL(" + column + ", '" + fallback + "')";
    }
}
```

业务层这一段，换数据库时**一个字都不用改**：

```java
class ProductDao {
    private final SqlBuilder sqlBuilder;              // 只依赖接口
    ProductDao(SqlBuilder sqlBuilder) { this.sqlBuilder = sqlBuilder; }

    List<String> findPage(Connection conn, int offset, int limit) throws SQLException {
        PageQuery query = sqlBuilder.buildPageQuery("product", "id", offset, limit);
        // 用 ? 占位符绑定参数，不把 offset/limit 直接拼进 SQL 字符串（防 SQL 注入）
        ...
    }
}
```

### 实测结果：两边查出来完全一样
`code/` 里跑的是两种**真实数据库引擎**：MySQL 8.4 跑在容器里；Oracle 镜像太重，用 H2 的 Oracle 兼容模式（`MODE=Oracle`）代替，它同样支持 `ROWNUM` / `NVL` / `DUAL`，用来验证 Oracle 方言的 SQL 真能执行。

```
[MySQL]  SQL = SELECT id, name FROM product ORDER BY id LIMIT ? OFFSET ?
[Oracle] SQL = SELECT * FROM (SELECT t.*, ROWNUM rn FROM (SELECT id, name FROM product ORDER BY id) t WHERE ROWNUM <= ?) WHERE rn > ?
MySQL  查出 : [4:商品4, 5:商品5, 6:商品6, 7:商品7, 8:商品8]
Oracle 查出 : [4:商品4, 5:商品5, 6:商品6, 7:商品7, 8:商品8]
两边结果一致？ true
```

## 三条路，按情况选（原题给的方案）

| 路子 | 怎么做 | 适合什么场景 |
|---|---|---|
| **ORM 框架** | MyBatis 用 `<databaseId>` 标签，同一方法配多段 SQL；Hibernate 靠 `Dialect` 自动翻译，你只写 HQL | 常规增删改查，最省事，优先选 |
| **自己封装 SqlBuilder** | 统一接口 + 各库实现 + 工厂/配置路由（就是本示例） | 绕不开原生 SQL、要精细控制 SQL 时 |
| **驱动与连接池可插拔** | HikariCP 配 `driver-class-name` 和 URL，启动时自动装配对应数据源 | 必做项，是上面两条的地基 |

驱动可插拔很好验证——换库只换一行 URL，JDBC 自己就认得连的是谁：

```
MySQL  连接认到的是 : MySQL 8.4.11
Oracle 连接认到的是 : H2 2.3.232 (2024-08-11)
```

## 一句提醒
- **能写标准语法就别用方言函数**。`SELECT` / `INSERT` / `JOIN` 这些各家都认，只有分页、空值函数、日期函数这类才需要下沉到 `SqlBuilder`。原题说得很实在：SQL 写标准语法，MySQL 和 PostgreSQL 就能共用一份。
- 分页的 `offset` / `limit` 是代码算出来的整数，也照样用 `?` 绑定，不要拼字符串——习惯要养好。
- 真正换库的成本不在 SQL，而在**数据类型**（`DATETIME` vs `DATE`）和**事务/隔离级别**的差异，上线前测试要覆盖到。
