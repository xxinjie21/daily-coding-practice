# 让你设计一个 HashMap，怎么设计？

## ① 一句话题目（大白话）
让你从零写一个「键值对」存储：给一个 key（比如用户名），能快速存进、也能快速把对应的值取出来。这正是 Java 里 `HashMap` 干的事。

## ② 为什么会有这问题？
想象一排带编号的储物柜（数组），你要存东西，得先按「钥匙的长相」算出一个柜子号。麻烦有两件：
- 钥匙千奇百怪，怎么算出**均匀**的柜子号，别全挤在一个柜子里？
- 万一两把不同的钥匙算出了**同一个柜子号**（哈希冲突），怎么办？

把这两件事办漂亮，就是设计 HashMap 的核心。

## ③ 怎么做（照着 JDK 的思路来）
整体结构：**数组（一排柜子）+ 链表（每个柜子里挂的钥匙串）**。再补一条：链表太长（长度 > 8）且柜子总数够多（> 64）时，链表换成红黑树，查找从「一条条数」变成「折半找」，避免被恶意构造的 key 拖垮。

四步关键设计：

**1) 二次扰动散列——让柜子号撒得匀**
别直接拿 `key.hashCode()` 当柜子号。很多对象的 hashCode 低位总是一样（比如老是 0），直接取低位会全挤一个柜子。把「高 16 位」和「低 16 位」异或一下，让高位也参与算号：
```java
int h = key.hashCode();
int hash = h ^ (h >>> 16);   // 高位低位搅在一起
```
> 比喻：柜子号不能只看钥匙某一个齿，要把整把钥匙的信息都揉进去，才分得开。

**2) 容量固定为 2 的幂——取模变位运算**
柜子数量设成 16、32、64…（2 的幂）。这样「柜子号 = hash % 容量」可以写成「`hash & (容量-1)`」，位运算比除法快得多。
```java
int index = hash & (capacity - 1);
```

**3) 数组 + 链表解决冲突——同一个柜子挂一串**
算出 `index` 后去 `table[index]` 这个桶。桶里用链表把冲突的元素串起来：存/取时先定位桶，再在链子上挨个比 key。

**4) 负载因子 0.75 + 翻倍扩容——装太满就搬家**
元素数超过「容量 × 0.75」就扩容：容量翻倍，把老数据重新分配。巧妙的是因为容量翻倍，**老数据要么留在原柜子，要么搬到「原柜子号 + 旧容量」的新柜子**——不用重算完整 hash，只看新增的那一位是 0 还是 1：
```java
int newIdx = (hash & oldCap) == 0 ? oldIdx : oldIdx + oldCap;
```
> 比喻：16 个柜子变 32 个，每个旧柜子里的东西，一半留下、一半搬到对面新柜子，只看钥匙多出来的那一位是 0 还是 1。

## ④ 一句易错提醒
**自定义对象当 key，必须同时重写 `hashCode()` 和 `equals()`；而且 key 最好用不可变类（如 String、Integer）。** 要是 key 存进去之后被改了内容，它的 hashCode 就变了，下次按新 hashCode 算出的柜子号对不上，数据就「丢了」——明明存了却取不出来。
