# 调用第三方接口要注意什么：别让"别人家的服务"拖垮自己

## 一句话说清题目

我们系统要调用别人的接口（比如支付、短信、物流、地图），光发一个 HTTP 请求是不够的。**要考虑的是：对方慢、对方挂、对方超时、请求重复发，我们这边怎么不跟着一起死。**

## 为什么会有这个问题

把调用第三方接口想成**叫外卖**：

- 你下单后一直站在门口等，不设"最多等 30 分钟"的规矩 → 你这一天啥也别干了。**这就是不设超时**。
- 外卖没来你就一直重拨电话，拨了 20 次 → 商家被打爆，你也别的事没做。**这就是无脑重试**。
- 这家店连着几次都不出餐了，你还继续下单 → 干脆先停几天，改吃楼下便利店。**这就是熔断降级**。
- 同一单你手抖点了两次"下单" → 送来两份，还扣两次钱。**这就是没有幂等**。

关键认知：**第三方的可用性不由你控制，但"被它拖垮"是可以避免的。** 我们做的一切，都是给自己加一层"防护垫"。

## 怎么做：六道防线

```
我们的业务代码
      │
      ▼
① 超时控制 ──► ② 重试(带退避) ──► ③ 熔断降级 ──► ④ 幂等去重 ──► ⑤ 数据安全 ──► ⑥ 监控埋点
  等太久就放弃    抖动才重试       错太多就暂停     重复请求丢掉     密钥别外泄     出问题能知道
      │                                                                              │
      └────────────────────────── 每一层都为了「别被拖垮」 ────────────────────────────┘
```

### ① 超时控制：第一道防线，也是最重要的一道

很多人压根不设超时，默认就是"等到天荒地老"。对方卡住不回，我们的线程全被占着，**连接池满了，自己先崩**。

```java
// 连接超时（TCP 握手多久算失败）：1~3 秒
// 读取超时（连上了但对方多久不回数据算失败）：5~10 秒
```

用 Spring 的 `RestTemplate` 或 `WebClient` 都**必须手动配**这两项，不配就是没防护。

### ② 重试：网络抖动可以重试，有"副作用"的操作绝对不能

- **可以重试**：查询类接口（查天气、查汇率）。失败了重试 2~3 次没关系，反正不改变对方状态。
- **不能重试**：支付、扣款、下单、发短信这类**带副作用**的接口。你重试一次，可能就多扣一笔钱。

重试要配**退避策略**（backoff）：别一秒内狂打三次，而是第一次等 1 秒、第二次等 2 秒，给对方喘息时间。

### ③ 熔断降级：错太多了就主动"断开"

思路和家里的**空气开关**一样：短路了直接跳闸，别一直烧。

| 状态 | 行为 |
|---|---|
| 关闭（正常） | 请求正常发出去 |
| 打开（熔断中） | 请求**根本不发**，直接走降级逻辑（本地缓存 / 默认值） |
| 半开（试探） | 放一小部分请求过去试试，好了就恢复，还不行就继续熔断 |

常见规则：**最近一段时间错误率超过 50%，就熔断几分钟**。工具可选 Alibaba Sentinel 或 resilience4j（Hystrix 已停更）。

### ④ 幂等：同一个请求来两次，效果只算一次

场景：订单创建后要回调第三方物流下单。网络抖动导致我们重发了，或者对方超时了但其实已经处理成功，**就会重复触发**。

做法很简单：**给每次操作生成一个唯一任务 ID，存到 Redis（可以理解成一个公共的记事本）**，带过期时间。

```java
// 第一次来：Redis 里没有 → 放行，并写入 key，10 分钟过期
// 10 分钟内又来：Redis 里已经有 → 直接忽略，当成功返回
```

### ⑤ 数据安全：密钥别写进日志

- 敏感字段（token、用户 ID）走 **HTTPS**（加密的传输通道，中间人抓包看不懂）。
- 有些老系统要求把 `secret key` 放在请求头里传 —— **千万别打日志**，日志泄露就是事故。

### ⑥ 监控告警：出问题要能第一时间知道

每个外部调用都打埋点，统计**成功率**和 **P95 耗时**（把耗时从小到大排，95% 的请求都快于这个值，比平均值更能反映"最慢的那批人有多慢"）。

Prometheus + Grafana 配个看板，再挂 AlertManager 发钉钉通知。

## 一句提醒

**第三方接口的稳定性你管不了，但"超时 + 熔断 + 幂等"这三样是保命符。** 尤其记住：**支付类接口永远不要自动重试**——宁可让用户手动点一次，也不要重复扣款。
