# 配置中心挂了怎么办：本地缓存 + 默认值 + 熔断三件套

## 一句话题目

配置中心（专门存各种配置参数的"总服务器"）突然宕机，各个微服务不能跟着一起躺平——靠手里的旧配置副本和兜底默认值继续跑，只是功能弱一点，但别死。

## 为什么会有这问题

把配置中心想成小区的**自来水厂**，微服务是家家户户。平时大家拧开水龙头就有水（远程拉配置）。可水厂一检修（配置中心挂了），你家总不能天天喝不上水吧？所以家里得先备个**水箱**（本地缓存）：水厂好的时候把水存起来，检修时靠水箱撑几天。

更麻烦的是，如果每户都派人去水厂门口守着问"好了没"（不断重试），维修师傅别干活了，门口也会被踩塌——这就是"雪崩"。所以还得有个**门卫**（熔断器）：问了几次都不行，就拦住后面的人别再问了，让大家先回去用水箱的水。

## 怎么做（对应代码里的四条线）

代码在 `code/src/main/java/Demo.java`：配置中心是本进程内的一个真实 HTTP 服务（端口 8899，`GET /config` 返回全量配置），客户端用 OkHttp 真实调用，故障场景全程实跑。

**① 启动拉全量，写本地文件（水箱先蓄水）**

客户端启动时调一次 `GET /config`，把拿到的配置写进本地文件 `config-cache.json`（Apollo、Nacos 也是这么干的）：

```java
String body = fetchAll();                       // OkHttp 拉全量
memory = mapper.readValue(body, ...);           // 内存放一份，平时就读它
Files.writeString(CACHE_FILE, body);            // 本地文件再存一份，防重启
```

配置中心炸了也不怕：下次重启时 `startup()` 拉取失败，会自动改读 `config-cache.json`，"至少能起来一半"。

**② 内存持有 + 定时轮询刷新（水箱持续补水）**

运行中每 30 秒（演示里压缩成 2 秒）轮询一次，有变更就拉下来，内存和本地文件一起更新：

```java
if (!remote.equals(memory)) {
    memory = remote;
    Files.writeString(CACHE_FILE, body);   // 有更新才动本地文件
}
```

哪怕中间断个几十秒，内存里还有旧配置可用，服务不会立刻崩。

**③ 默认值兜底（瓶装水）**

对应 Spring 的 `@Value("${xx:default}")`——远程拿不到，直接用代码里写死的保命值，保证不空指针：

```java
String get(String key, String defaultValue) {
    return memory.getOrDefault(key, defaultValue);
}
```

比如 `@Value("${timeout.ms:500}")` 里的 500 就是保命值：配置中心没了也压根不经过它。

**④ 熔断式降级（门卫拦住白跑的人）**

连续失败达到阈值，熔断器自动打开，之后请求**根本发不出去**，直接用内存缓存——避免大家一起撞门把故障放大。本 Demo 用 Resilience4j（Hystrix 的现代替代品）的真实熔断器：

```java
CircuitBreakerConfig.custom()
    .slidingWindowType(CircuitBreakerConfig.SlidingWindowType.COUNT_BASED)
    .slidingWindowSize(5)
    .minimumNumberOfCalls(3)    // 不满 3 次不算账，防网络抖两下就误打开
    .failureRateThreshold(50)   // 失败率过半就打开
    .waitDurationInOpenState(Duration.ofSeconds(4))
    .build();
```

熔断器有三个状态，和生活里对应得很贴切：

| 状态 | 含义 | 客户端行为 |
|---|---|---|
| CLOSED（关） | 一切正常 | 正常轮询配置中心 |
| OPEN（开） | 连续失败，熔断中 | 请求不发出去，直接用内存缓存 |
| HALF_OPEN（半开） | 等了 4 秒，放一次试探 | 试一次：成功就恢复，失败就重新打开 |

故障时刻谁在兜底，一张表看全：

| 发生了什么 | 谁兜底 | 用户感知 |
|---|---|---|
| 轮询失败几十秒 | 内存里的旧配置 | 无感 |
| 熔断器打开 | 内存缓存（且不再发请求） | 无感，还省了无效请求 |
| 服务重启 + 中心挂着 | 本地 `config-cache.json` | 能起来，用的是旧配置 |
| 连本地文件都没有 | 代码默认值 | 能跑，功能可能弱一点 |

## 一句线上提醒

本地缓存是**旧配置**——靠它续命期间，你在配置中心改的参数是不生效的，恢复后要确认有没有漏拉的变更；另外熔断阈值别配得太敏感（`minimumNumberOfCalls` 就是防这个的），否则网络抖两下就把熔断器打开，反而看不到最新配置了。
