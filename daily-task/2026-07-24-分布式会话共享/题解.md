# 分布式会话共享：多台服务器怎么都认得同一个登录用户

## ① 一句话题目
网站从一台服务器扩成好几台后，用户在 A 机器登录成功，下次请求却被分到 B 机器，B 不认识他、提示「没登录」。怎么让所有机器都认得同一个已登录的用户？

## ② 生活比喻
「登录状态」就像去游乐园买的手环，检票时工作人员确认「这人买过票」。单台服务器时代只有一个检票口，手环记在这个口的小本子上，没问题。现在开了好几个检票口（多台服务器），你在 1 号口登记了手环，走到 3 号口时，3 号口的小本子上根本没有你的记录——它当然说「没见过你，重新买票吧」。

## ③ 怎么做
核心就一句话：把「登录档案袋」（Session）从单台机内存搬到大家共用的 Redis 公共储物柜，谁拿着 sessionId 都能取到同一份。

按主方案走四步：

1. 用户登录成功，服务器生成随机 sessionId（钥匙编号），把用户档案写进 Redis，key 就是这个 sessionId。
2. 通过 Cookie 把 sessionId 发回浏览器，之后每次请求自动带上。
3. 负载均衡把请求分到任意一台机，这台机拿 sessionId 去 Redis 取档案——落到哪台都认得。
4. 给 key 设 TTL（过期时间，如 30 分钟），活跃就续期；踢人下线只需删 Redis 里这个 key。

举个真例子：
- 用户在 A 机登录，A 写 Redis：`"sid_888" → {userId:42, role:user}`；
- 下次请求被分到 B 机，B 拿 Cookie 里的 sid_888 去 Redis 一查，立刻读出 userId:42——B 也认得他了。

关键方法（`code/Demo.java`）：`demoRedisSession` 里两台 `ServerNode` 共用 `fakeRedis`，一台写入另一台立刻读到；`logout` 删 key 即踢人。

其他方案（了解即可）：JWT 自带回防伪章、服务端不存状态，但难中途作废；IP Hash 按 IP 固定分机，宕机即丢会话，只当救急。

## ④ 一句提醒
把会话状态从机器里剥离出来是水平扩展的前提：普通业务优先 Redis（可控、能踢人），对外 API 用 JWT（无状态、省查询），IP Hash 只当救急——核心权衡是你更需要「随时管控」还是「极致无状态」。
