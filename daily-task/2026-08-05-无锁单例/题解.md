# 无锁单例：不加 synchronized 也能写出线程安全的单例

## ① 一句话题目（大白话）
**单例**，就是一个类在程序运行期间「只能有一个对象」。比如公司里**唯一的公章**——不能每个人都偷偷刻一个，否则盖章就乱套了。
麻烦在：多线程（多个同事）同时来「领公章」，如果不加保护，可能有人领到 A、有人领到 B，**出了两个就不是单例了**。
题目问的就是：能不能**不写任何锁**（不写 synchronized / Lock），也让它只产生一个对象？

## ② 为什么会有这问题（生活比喻）
想象 50 个人同时冲进办公室喊「我要公章！」。
- 如果没人维持秩序（没锁），两个人可能同时去柜子里拿，结果**各刻了一个**，公司就有两个公章了——灾难。
- 通常的解决是门口加个保安（synchronized 锁），一次只放一个人进去。但题目偏偏说「**不许加保安**」，那怎么办？

答案是：**把「只建一次」这件事，交给比保安更靠谱的「大楼规矩」（JVM 的类加载机制）来管**——它在底层已经保证了一间屋子（一个类）只会被布置一次。

## ③ 怎么做（核心思路）
两套「不加锁也安全」的主流写法：

**写法一：静态内部类（懒加载登记式）——最推荐**
把实例藏在一个 `private` 的内部类里。外部类加载时，内部类**不会**被加载；只有第一次调用 `getInstance()` 时，才触发内部类加载。
而 **JVM 在加载一个类时会自动加一把内部锁，保证这个类只初始化一次**——这把锁是 JVM 替我们加的，代码里一行锁都不用写。既省资源（懒加载，用到才建），又线程安全。

**写法二：枚举（Effective Java 推荐）——最省事最安全**
直接用 `enum`，把实例写成 `INSTANCE`。枚举的实例**天生由 JVM 保证只创建一次**，而且天然防反射、防反序列化破坏，代码最短。

> 另有两种「提一下但不推荐自己折腾」的写法：
> - **饿汉式**：类一加载就把实例 new 好，最简单，但如果这单例很重、启动时又用不到，就白占资源。
> - **双重检查锁 DCL + volatile**：用 `volatile` 防止「对象还没造完就被读到」，也得配合一次轻量锁。**Effective Java 明确说过：想实现单例，用枚举比 DCL 简洁又安全**，新手别自己造 DCL 轮子。

### 四种写法速查表
| 写法 | 是否需要锁 | 是否懒加载 | 一句话点评 |
|------|-----------|-----------|-----------|
| 静态内部类 | 否（JVM 兜底） | 是 | 推荐：用到才建，安全又省 |
| 枚举 | 否（JVM 兜底） | 是 | 最省事最安全，防反射/反序列化 |
| 饿汉式 | 否 | 否 | 简单，但重对象可能浪费 |
| DCL + volatile | 轻量锁 + volatile | 是 | 能写对，但没必要自己造 |

`code/Demo.java` 里把四种都实现了，并起 **50 个线程同时来领单例**，验证它们拿到的**全是同一个对象**（不加锁也安全）。

## ④ 一句线上提醒
**别用「懒汉式 + 不加锁」的裸奔写法**（先 `if (instance == null) instance = new ...`）——多线程下绝对会建出多个对象；要么用静态内部类 / 枚举，要么就老实加 `volatile` 配 DCL。新手首选**枚举或静态内部类**，别在锁上炫技。
