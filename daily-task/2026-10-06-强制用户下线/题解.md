# 强制用户下线：怎么让一个已经登录的人立刻失效

## 一句话
用户已经登录了，但我要让他**马上**掉线——比如封号、改密码后要求全部重新登录、或者提示「你的账号在别处登录了」。

## 为什么这件事不好做

先看个反例。很多老项目把登录状态直接存在服务器的内存里（一个 `Map<token, userId>`）。
这就像**门禁卡记录只存在 1 号门保安手里**：你跑去跟 2 号门保安说「把这张卡作废」，他一脸茫然——他手上根本没这份记录。

服务器一多（哪怕只是加了台负载均衡），请求就可能落到任何一台机器上。A 机踢掉的人，B 机照样认，用户会觉得「踢了又活了」。

所以第一件必须做的事：**把登录状态从「某台服务器的内存」搬到「大家都能看到的地方」——Redis。**

## 核心思路：四步

### ① 登录时，把会话集中存进 Redis

登录成功后，把 token 存进 Redis，值放 userId，并挂上过期时间：

```java
// code/src/main/java/Demo.java
redis.set(TOKEN_KEY + token, userId, SetParams.setParams().ex(1800)); // 30 分钟不活动自动失效
```

`token` 就是「服务器发给你的那张会员卡卡号」，之后每个请求都要带上它。

### ② 踢人 = 把这条记录删掉

```java
redis.del(TOKEN_KEY + token);
```

记录没了，后续请求拿这个 token 来查，自然查不到。

### ③ 光删不够，还得「广播」一声

因为客户端这会儿可能正开着页面在操作。要让它立刻退出，得主动通知。用 Redis 的**发布/订阅（Pub/Sub）**：踢人的那一方 `publish`，所有网关实例都 `subscribe` 着同一个频道。

```java
redis.publish(LOGOUT_CHANNEL, token);   // LOGOUT_CHANNEL = "user-logout"
```

这就像**总机房一按「作废」，所有门的保安对讲机同时响**。

> 补充：通知到浏览器那一段通常用 WebSocket（服务端主动推给页面），属于前端通道；本题用 Pub/Sub 演示的是「服务端之间怎么实时同步这个决定」。

### ④ 网关拦截后续请求

每个网关实例收到通知后，把 token 记进自己的**本地名单**；下一个请求进来，先查本地名单，命中就直接拒绝；本地没命中，再回 Redis 确认会话还在不在：

```java
boolean allowed = !offlineSet.contains(token) && redis.exists(TOKEN_KEY + token);
```

为什么还要本地名单？它是「已经确定被踢」的快速通道——网关可以顺手把这个用户的长连接断开、把页面踢回登录页，不用每次都为这几个 token 去问 Redis。

### 整条调用链

```
运营后台点「强制下线」
  → redis.del(login:token:tk-u1001-1)          # 会话作废
  → redis.publish("user-logout", "tk-u1001-1") # 广播
        ├─ 网关-1 订阅线程收到 → 本地名单 +tk-u1001-1 → 后续请求拒绝
        └─ 网关-2 订阅线程收到 → 本地名单 +tk-u1001-1 → 后续请求拒绝
  → 前端收到 WebSocket 消息 → 跳转登录页
```

## 踢人粒度：按设备 还是 按账号

| 粒度 | 做法 | 典型场景 |
|---|---|---|
| 按设备踢 | 只删这一个 token | 踢掉「我在网吧登录的那台」，其他设备不受影响 |
| 按账号踢 | 该账号名下所有 token 全删 | 封号、改密码后要求全部重新登录 |

为了支持「按账号踢」，登录时顺手记一份反向索引（一个账号有哪些 token）：

```java
redis.sadd(USER_TOKENS_KEY + userId, token);   // USER_TOKENS_KEY = "login:user:"
```

踢账号时把它取出来逐个删：

```java
Set<String> tokens = redis.smembers(USER_TOKENS_KEY + userId);
for (String token : tokens) {
    redis.del(TOKEN_KEY + token);
    redis.publish(LOGOUT_CHANNEL, token);
}
```

两种粒度最后都归到同一件事——**删 token + 广播 token**，所以网关那边只需要维护一份 token 名单，不用区分类型。

## 一句提醒

**别把登录状态放在单机内存里。** 单机时代那个 `Map` 能跑，一旦多机部署就会「踢了又活」。会话必须落到外部存储；Redis 是最通用的选择，它顺手还把 Pub/Sub 这个实时通知能力一起给了你。另外记得给会话**设过期时间**，否则 Redis 里会攒下一堆永远不清理的僵尸 token。
